TeamTopo

Team Topologies diagrams from text, drawn the way the book draws them.

Syntax reference

Teams

stream id "Label"Stream-aligned team: a full-width lane. Lanes stack in declaration order. Also stream-aligned, sa.
enabling id "Label"Enabling team: a tall bar crossing the lanes it facilitates. Also en.
subsystem id "Label"Complicated-subsystem team: an octagon embedded on the first lane it serves. Also cs.
platform id "Label"Platform team: a full-width bar beneath the lanes. Also pf.
platform id "Label" { … }Platform grouping: a platform made of inner teams.
group id "Label" [kind="value stream"] { … }Any other boundary around teams.
[size=7, note="text"]Attributes after the label. note shows under the name; everything else is a tooltip.

Interactions

a <--> bCollaboration: a parallelogram bridging the two teams.
provider --> consumerX-as-a-Service: a wedge, wide at the provider, pointed at the consumer. <-- reverses it.
enabler ~~> teamFacilitating: the dotted patch where the enabling bar crosses the team. <~~ reverses it.
a --> b, c : labelComma lists fan out; one wedge spans every consumer. A label after : is drawn on the interaction.
a --> b : label [duration="Q3", soon]Attributes. duration fills the Team API table; soon marks an interaction expected soon (dashed, faded).
api id { field: value … }Team API fields the diagram cannot infer: focus, software, SLE, versioning, wiki, chat, sync, working on, ways of working, improvements. Click a team in the diagram to see its Team API.

Directives

teamTopologyMust be the first line.
title TextDiagram title.
flow [Text]Draws the flow-of-change arrow. Defaults to "Flow of change".
legendAdds a key for shapes and interaction modes.
%% or //Comment to end of line.

Example

teamTopology
  title Checkout domain
  flow

  stream   checkout "Checkout"
  enabling devex    "DevEx"
  platform infra    "Infrastructure" {
    stream k8s "Kubernetes"
  }

  k8s   --> checkout : runtime
  devex ~~> checkout : CI coaching
